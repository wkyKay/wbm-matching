## 同一排名，两套评价

用 Q、C 表示查询和候选的缺陷标签集合。

| 评价 | 相关性 | 指标 |
|---|---|---|
| exact | Q=C 才相关 | Hit、Precision、Recall、AP/mAP |
| coverage | g=\|Q∩C\|/\|Q\| | MeanCoverage、Coverage-nDCG |
| FullCoverage | Q⊆C，允许额外标签 | FullCoverage 的 Hit、Precision、Recall、AP/mAP |

K 固定为 1、5、10、20、50、100、500。每种二值相关性中，前 K 命中数为 H、完整候选库正样本数为 R：

- Hit@K 判断 H 是否大于零；Precision@K=H/K；Recall@K=H/R。
- AP@K 是前 K 每个命中位置的 Precision 之和再除以 R；不是除以 min(R,K)。mAP 是 query 的 AP 平均。
- MeanCoverage@K 是前 K 覆盖比例之和除以 K；nDCG 使用线性增益 g/log₂(rank+1)，理想排序取完整候选库。
- 返回不足 K 的空位贡献零。R=0 时该 query 不参加对应 Recall/AP 平均，但保留其他指标；IDCG=0 时 nDCG 也不参加该项平均。

报告总体 query 平均、完整组合类别宏平均、单/混合和标签数量分组。没有启用部分覆盖阈值 τ。按方法分数排序，真实标签只用于评价；同分采用固定 SHA-256 次序，Wu 另保留粗筛距离次排序键。实现见 [exact](../shared/exact_metrics.py)、[coverage](../shared/coverage_metrics.py)。

保存的 `rankings.csv` 仅为 Top-500，不是全部候选排名。Wu 只对粗筛入选者做最终 NCC，Recall/AP 分母仍取完整候选库。

## 跨组合是独立协议

`coverage_cross_combination_v1` 在方法粗筛和打分前，排除自身及完整标签组合相同的候选，只报告 coverage。这是利用标签定义候选资格的诊断实验，不是普通检索的替代成绩。

当前 test 每 query 剩 6,999–7,170 个候选；999 个 query 没有 FullCoverage 正样本，对应 Recall/AP 有效 query 为 6,200，其他指标仍使用全部 7,199 个 query。七方法已完成，其中 F 是旧径向面积模型。实现见 [cross_combination.py](../shared/cross_combination.py)，结果与普通协议分表。

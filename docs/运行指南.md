# 运行指南

以下是入口说明，不代表需要重跑已有结果。先阅读 [实验设计](实验设计.md)、[数据划分](数据划分.md) 和目标方法 README；使用原 PyTorch/CUDA 环境，在仓库根目录操作。

## 训练与评价分开

| 方法 | 训练入口 | 统一评价需要什么 |
|---|---|---|
| Wu、WBBS、WMHD | 无需训练 | 对应 `methods/<方法>/config.json` |
| Yu、Nakazawa | `methods/<方法>/<方法>.py --stage train` | 用 `--source-run` 指向已完成训练目录 |
| WaPIRL | `methods/wapirl/wapirl.py`，没有 `--stage train` 参数 | 同样用 `--source-run` 指向已完成训练目录 |

训练入口支持 `--config`、`--output-dir`；CNN 使用 `--device cuda`，断点续训按方法 README 使用 `--resume`。统一评价入口是 [scripts/evaluate.py](../scripts/evaluate.py)，不会隐式训练：

```text
python -u scripts/evaluate.py --config methods/<方法>/config.json \
  --split <valid或test> --output-dir artifacts/<本次评价的时间型run_id> \
  [--source-run <已完成训练目录>] [--device cuda] [--rank-workers <进程数>]
```

尖括号和方括号是需要替换/选用的说明，不可原样执行。参数在 valid 确定后再显式运行 test。跨组合评价额外指定 `--exclude-exact`，使用独立输出目录。smoke 换成该方法的 `smoke.json`，只能检查小 valid，不能用于正式成绩或 test。

统一评价没有 `--resume`，输出目录必须是新的；失败目录保留，重跑另建目录。`--source-run` 不会绕过模型、配置或源码签名检查。

## 新运行必须登记时间身份

在真实启动时持久化 `run_id=YYYYMMDDTHHMMSS+0800__稳定语义key` 和带时区的 `started_at`。训练与每次独立评价分别登记；同一排名的 exact/coverage 共用评价身份。不要复制历史示例路径覆盖旧产物。

**当前登记器对历史实验仍使用完成标记 mtime。接入第一个新实验前，须先支持读取持久化的真实时间身份，不能让新运行静默回退到 mtime。** 这是接入前置要求，不表示 CLI 已自动实现。完整规则见 [AGENTS.md](../AGENTS.md)。

## 完成后做什么

1. 核对完成标记、报告哈希、训练来源和完整候选身份；仅有部分 CSV 不算完成。
2. 更新相邻主项目 `results_catalog/sources.json`，记录路径、协议、选择过程及是否事后实验。
3. 在服务器主项目根目录运行 `python3 results_catalog/build.py collect --workspace /data/wangkaiyan2024`，再运行 `python3 results_catalog/build.py check`。
4. 同步生成文件，更新 [实验结果](实验结果.md) 的简短结论和相关方法说明，再同步两仓库本地、服务器、GitHub。原始产物不移动。

产物含义见 [实验结果](实验结果.md)。计时比较中，`ranking_total_seconds` 是各 query 排序耗时之和；`ranking_wall_seconds` 是排名阶段实际等待时间，含并行管理、评价与写出，二者不能互换。详细参数和实现约定仍以各方法 README 为准。

## 数据与评价

Mixed-WM38 原始 38,015 条按完整 0/1/2/3 像素精确去重，每组保留最小原始 ID；过滤 1,024 条冗余后有 35,991 张缺陷图和 1,000 张 Normal。缺陷图按 37 种完整标签组合分层，seed=2026。

| 集合 | 图像数 | query 数 | 每个 query 的候选数 |
|---|---:|---:|---:|
| train | 25,193 | — | — |
| valid | 3,599 | 固定 500 | 3,598 |
| test | 7,199 | 全部 7,199 | 7,198 |

每个 query 检索同集合全部其他图像，排除自身。Normal 不入缺陷检索库；Yu 检测器所需 Normal 按 seed=2026 分为 700/100/200，写入运行目录，尚未独立中央冻结。`sample_id` 是原始 NPZ 行号，不重新编号。

标签顺序为 center、donut、edge-loc、edge-ring、loc、near-full、scratch、random。清单位于 `protocol/deduplicated/`、`protocol/retrieval_v1/`，加载时检查哈希，不重划或覆盖；具体文件和生成规则见[协议说明](../protocol/README.md)。

用 Q、C 表示查询与候选标签集合，以下指标评价同一排名：

| 评价 | 相关性 | 指标 |
|---|---|---|
| exact | Q=C | Hit、Precision、Recall、AP/mAP |
| coverage | g=\|Q∩C\|/\|Q\| | MeanCoverage、Coverage-nDCG |
| FullCoverage | Q⊆C，允许额外标签 | FullCoverage 的 Hit、Precision、Recall、AP/mAP |

K=1、5、10、20、50、100。前 K 命中数为 H，完整候选库正样本数为 R：Hit 判断 H>0，Precision=H/K，Recall=H/R；AP 是各命中位置的 Precision 之和除以 R，mAP 是 query 的 AP 平均，分母不是 min(R,K)。MeanCoverage 是前 K 覆盖比例之和除以 K；nDCG 使用线性增益 g/log₂(rank+1)，理想排序取完整候选库。

缺位贡献零。R=0 的 query 不参加对应 Recall/AP 平均，但保留其他指标；IDCG=0 时不参加 nDCG 平均。报告总体、完整组合类别宏平均、单/混合及标签数量分组，不启用部分覆盖阈值 τ。实现见 [exact](../shared/exact_metrics.py)、[coverage](../shared/coverage_metrics.py)。

普通检索按方法分数排序，真实标签只用于评价；同分用固定 SHA-256 次序，Wu 另保留粗筛距离次排序键。新评价默认保存 Top-100，历史 Top-500 原样保留，均不能称为完整排名；Wu 只对粗筛入选者做 NCC，但 Recall/AP 分母仍取完整候选库。

## 跨组合评价

`coverage_cross_combination_v1` 在粗筛、打分和排序**之前**排除完整标签组合相同的候选，只输出 coverage。例：query={A,B} 时删除 {A,B}，保留 {A,B,C}、{A} 和 {C}，覆盖率分别为1、0.5、0。原始图像及冻结清单不改，标签仅用于候选资格，不交给方法打分。

| 集合 | 保留 query | 每 query 剩余候选 | 无 FullCoverage 正样本的 query |
|---|---:|---:|---:|
| valid | 500 | 3,499–3,585 | 72 |
| test | 7,199 | 6,999–7,170 | 999 |

AP/Recall 分母和 coverage IDCG 使用过滤后的完整候选库。test 的 FullCoverage Recall/AP 有效 query=6,200，其余指标保留全部7,199个 query；不能先删除999个 query再统一求所有均值。Wu 必须重新粗筛，不能裁掉旧 Top-500 里的同组合项充当新排名。

这是依赖真值的独立诊断，是在已有 test 上追加的分析，不能写成部署时无标签过滤功能或原 test 前预注册协议。七方法已完成，其中 F 是2026-11-11旧径向面积来源，不能替代当前cc8。实现见 [cross_combination.py](../shared/cross_combination.py)，成绩单列于[实验结果](对比方法实验结果.md#跨组合检索的结论)。

## 如何运行

已有正式成绩直接读取结果文档和登记表，本轮无需重跑。以下为将来新增运行的模板，不能把示例目录当作已启动实验；新运行须先落实真实时间身份及签名保护。

在仓库根目录使用原 PyTorch/CUDA 环境，依赖见 `requirements.txt`，默认数据为 `../data/wm38k/Wafer_Map_Datasets.npz`。公共实现位于 `shared/`，回归检查位于 `tests/`。

| 方法 | 训练入口 | 评价来源 |
|---|---|---|
| Wu、WBBS、WMHD | 无需训练 | 对应 `methods/<方法>/config.json` |
| Yu、Nakazawa | `methods/<方法>/<方法>.py --stage train` | `--source-run` 指向已完成训练目录 |
| WaPIRL | `methods/wapirl/wapirl.py`，没有 `--stage train` | 同上 |

训练可指定 `--config`、`--output-dir`、`--device cuda`；续训按方法 README 使用 `--resume`。统一评价只读来源，不隐式训练：

```text
python -u scripts/evaluate.py --config methods/<方法>/config.json \
  --split <valid或test> --output-dir artifacts/<本次评价的时间型run_id> \
  [--source-run <已完成训练目录>] [--device cuda] [--rank-workers <进程数>]
```

尖括号和方括号是待替换/选用项。参数先在 valid 确定，再显式运行 test；跨组合追加 `--exclude-exact` 并使用独立目录。smoke 换成该方法的 `smoke.json`，仅检查小 valid，不运行 test、不算正式成绩。

训练目录用 `--source-run` 显式传入：Yu、Nakazawa、WaPIRL 不能指向旧评价目录。Yu 主比较用默认 `--variant global`；`predicted_class` 单独登记。CPU特征提取用 `--workers`，query并行用 `--rank-workers`，二者不是同一个阶段。

正式统一入口默认K=1/5/10/20/50/100；smoke仍用1/5/10/20。旧Wu/Yu方法配置中的`ks`属于冻结训练／原入口签名，保留原值；当前评价使用`scripts/evaluate.py`，其K独立于训练配置。Wu粗筛数量仍是500，valid query仍是500，均不是评价K。

统一评价没有 `--resume`，输出目录必须是新的；失败产物保留，重跑另建目录。`--source-run` 不会绕过配置、源码或模型签名检查。新运行先落实“保存与登记”中的真实时间身份要求。

新训练和每次独立评价分别保存真实启动时间型 `run_id=YYYYMMDDTHHMMSS+0800__稳定语义key`、带时区的 `started_at`；同一排名的 exact/coverage 共用身份。**登记器目前对历史结果使用完成标记 mtime；接入第一项新实验前须支持读取真实时间身份，不能静默回退。**

完成后核对产物，更新相邻主项目唯一的 `results_catalog/sources.json`，在服务器主项目根目录运行 `python3 results_catalog/build.py collect --workspace /data/wangkaiyan2024` 和 `python3 results_catalog/build.py check`。随后更新本页简短结论，同步两仓库本地、服务器和 GitHub。细则见 [AGENTS.md](../AGENTS.md)。模型、数据、缓存和排名原位保留，不随 Git 发布。
